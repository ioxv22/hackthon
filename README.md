# AIGov Compass

**The right model, with clear evidence, and a human decision.**
From government use case to evidence-backed AI approval.

## دليل التسليم السريع بالعربية

هذا نموذج أولي للهاكثون، وليس خدمة حكومية أو اعتماداً أو شهادة امتثال. يبدأ التطبيق في **الوضع التجريبي** ببيانات افتراضية ثابتة، ولا يتصل بمزودي النماذج. هدف خفض وقت التقييم البالغ ٨٠٪ غير مقاس أو مضمون.

### تشغيل العرض

1. افتح `index.html` في متصفح حديث، أو شغّل الخادم المحلي وفق خطوات Live أدناه.
2. لعرض مسار التحسين الجديد: افتح **ملاءمة الدور والتحسين** أو اضغط **شاهد التحسين · ٩٠ ثانية**. يبدأ العرض من ملف جهة خيالي ونتائج محاكاة، ولا يرسل طلباً خارجياً.
3. أظهر الاستجابة غير المدعومة، ثم اختر مهمة «ربط الإجابات بمراجع مراجعة» وأعد الاختبار. يحتفظ الموقع بالإصدار السابق، وتبقى نتيجة اختبار حقن التعليمات ظاهرة كمشكلة غير محسومة.
4. سجّل قرار المراجع «يتطلب تغييرات» لبيان أن التحسين الجزئي لا يعني الموافقة. جواز التقييم JSON يتضمن ملف الاستخدام، وإصدار الإعداد، والاختبارات، والنواقص، وقرار المراجع.
5. تبقى رحلة التحكيم الأصلية متاحة من صفحة العرض، وهي منفصلة عن مسار التقييم والتحسين الجديد.
6. للموصل الحقيقي الموجود، اختر KILWA من المسار الجديد ثم افتح **المقارنة المباشرة**. لن يُرسل شيء تلقائياً؛ اختر اختباراً غير حساس واضغط الإرسال بنفسك بعد مراجعة تحذير الخصوصية. المسار المباشر الحالي يقارن سؤالاً مع مصدر الاختبار المحدد، وليس مجموعة اختبارات الدور الجديدة كاملة.
7. استخدم **إعادة ضبط العرض** فقط إذا أردت مسح بيانات العرض المحلية؛ لا تستخدمه لاستعادة نسخة احتياطية. تُحفظ بيانات العرض والاستيراد في تخزين المتصفح المحلي.

### مسار ملف الجهة وتقييم التحسين

- نماذج الجهات الثلاث (استفسارات الخدمات العامة، مساعدة المستندات الداخلية، والإرشاد بشأن الطلبات) أمثلة خيالية. عدّل الدور والمستخدمين واللغات والإجراءات المسموحة والمحظورة وحساسية البيانات ومرجع المستند ومعايير النجاح لكل استخدام.
- نتائج **Role Fit** منفصلة عن نتائج **Security & Responsible Behaviour**. كل سجل يعرض السؤال والسلوك المتوقع والاستجابة الفعلية وسبب النتيجة وطريقة التقييم. الاختبارات حالات استجابة محاكاة ثابتة؛ لا تتصل بنموذج ولا تقيس مجموعة مستخدمين فعلية.
- حصة الاجتياز محسوبة من حالات Pass/Fail في هذه المجموعة فقط. التغطية هي عدد الحالات المعروضة، ولا تثبت الأمن أو الإنصاف أو الالتزام القانوني. يظهر الفشل الحرج منفصلاً ولا تخفيه النسبة.
- المهام تعرض المشكلة والتغيير المقترح ونوع التغيير والمسؤول والدليل المطلوب. تغييرات التوجيه أو المستندات ليست بحد ذاتها ضوابط أمنية. إعادة الاختبار تنشئ إصدار إعداد جديداً ولا تستبدل النتائج السابقة.
- الموافقة تبقى بيد المراجع. يلزم إقرار مراجع بشري ومراجع أدلة لكل بوابة إلزامية، ولا يمكن تسجيل الموافقة عند وجود فشل/مراجعة غير محسومة أو دليل ناقص. إدخال مرجع دليل هو إقرار من المراجع وليس تحققاً آلياً من محتوى المستند.
- التخزين في المتصفح ليس نظاماً حكومياً محمياً ولا سجلاً مقاوماً للعبث. لا تضع بيانات شخصية أو مستندات سرية في ملفات التصدير أو أي موصل خارجي. كل النماذج والنتائج والقرارات المضافة لهذا المسار موسومة بأنها خيالية/محاكاة.
- «مساعد حكومي» مساعد محلي محدود النطاق: يشرح النتائج المفتوحة، والنواقص، والتحسينات والخطوة التالية من بيانات المشروع الموجودة في المتصفح. لا يتصل بخدمة خارجية، ولا يتلقى حقول ملف الجهة أو نصوص المستندات، ولا يستطيع تعديل الاختبارات أو الأدلة أو القرارات. الردود نص آمن وليست موافقة أو حكماً رسمياً.

### حالة التحقق لهذا التسليم

- اكتملت رحلة التحكيم الإرشادية في المتصفح، بما فيها منع الموافقة عند نقص الدليل، والموافقة البشرية التجريبية المكتملة، وتحديث الإصدار مع الاحتفاظ بالسجل السابق.
- اختُبر فشل Live بمحاكاة استجابة خادم HTTP 502: ظهر الخطأ وخيار إعادة المحاولة، ولم تُستبدل الردود بإجابات Demo. لم يُتصل بالمزود الحقيقي أثناء هذا الاختبار.
- اختُبر التبديل إلى العربية وRTL بعرض 375px في المتصفح دون تمرير أفقي. هذا اختبار viewport، وليس اختباراً على جهاز جوال فعلي.
- اجتازت اختبارات Node.js المركزة 13 اختباراً في قواعد التقييم والأدلة وملف الجهة. اختبارات موصلات Live تستخدم استجابات محلية وهمية؛ لم يُختبر اتصال خارجي في هذا التسليم.
- اختُبر المسار الإرشادي في متصفح محلياً: ظهور الحالات الثماني، المقارنة قبل/بعد، منع الانتقال قبل تأكيد مراجعة التغيير، وتسجيل قرار تجريبي «يتطلب تغييرات». اختُبر عرض المساعد لنص HTML كنص آمن، والعربية RTL في عرض 375px دون تمرير أفقي. تحقق المتصفح من بنية JSON للجواز ومن محتوى تقرير الطباعة؛ لم تُختبر نافذة الطباعة الفعلية أو حفظ الملف عبر مربع تنزيل النظام.
- لم يُعثر على دليل المسابقة ضمن ملفات المشروع؛ لذلك لا يمكن التحقق من مطابقة كل بند للمسابقة.

## Run the demo

### Demo Mode

Open `index.html` in a modern browser. Demo Mode uses fixed fictional data and does not call model services. Browser local storage holds the demonstration evaluations and optional public-data imports. Use **Reset demo** to clear local demo state and the imported dataset.

### Live Mode and API status

**API status:** “Government Assistant” is a bounded local helper and does not use an API. Live model comparison remains available through the local backend; current provider availability, identity, and data practices are unverified. The role-fit and improvement suite is Demo-only and does not run against a Live model.

1. Install Node.js 20.3 or newer.
2. Open a terminal in this folder.
3. Run `node server.js`.
4. Open `http://127.0.0.1:4173` (do not open the HTML as a `file://` URL for Live mode).
5. Select **Live model comparison**, switch to Live, use fictional/public non-sensitive text, and accept the data warning before the first request.

The backend uses a fixed allowlist for:

- `https://kilwaapi.vercel.app/kilwa-deepseek`
- `https://kilwaapi.vercel.app/kilwa-claude`

It calls each route with GET and URL-encodes the prompt using `URL.searchParams`. The server validates HTTP status and the `{status, model, reply}` response, limits prompts to 8,000 characters, request bodies to 40 KB, and provider replies to 1 MB, allows at most two concurrent provider requests, enforces a 30-second timeout, and supports client cancellation. Only source rows and fields referenced by the selected test are sent. It does not log prompts or replies. Provider identity and data practices are unverified; the provider-reported model name is not independently verified. GET URLs may be retained in provider infrastructure logs. Never send personal, confidential, or sensitive government information.

Live replies are not persisted in browser storage. Failures remain visible with retry; they are never replaced by demo answers. Demo evidence cannot qualify a live provider for approval.

## Five-minute judging flow

1. Select **Start judging demo**. It forces Demo Mode; it does not call external services.
2. Review the proposed use case and plan, then compare the fictional candidate profiles.
3. Open **Live model comparison** in Demo Mode and run the fixed fictional challenge suite.
4. Inspect the Sifr Assist case: missing mandatory evidence blocks approval regardless of suitability score.
5. Open the separate Noura Civic fictional evidence fixture, complete human review, and record the simulated internal decision.
6. Download the model passport JSON or print the evaluation report. For the seven-slide deck, open **Pitch & 90-day plan** and select **Print 7-slide deck**; choose “Save as PDF” in the browser print dialog.
7. Trigger a simulated model update from Deployment & monitoring. The previous record is retained; the new version requires reassessment.

The **Pitch & 90-day plan** page includes the five-minute outline, an independent 2–3 minute video script, a printable seven-slide deck, proposed 90-day milestones, and honest committee Q&A.

The **Idea & Impact** page provides a concise Arabic/English summary of the problem, solution, beneficiaries, validation needs, and proposed 90-day plan. Open it from the sidebar or the pitch page; its print button prints this page only. It is a future proposal, not a claim of a government partner, verified Live API, real government data use, or achieved 80% time savings.

## Open-data tests

The official Data Dubai page for **Annual Percentage Change in Consumer Price Index- Base Year 2021** was accessed on 2026-10-23. The metadata page described monthly/quarterly CPI changes and listed the dataset as Open, but its data tables displayed “No data available” and the data-download controls were disabled in the accessed session. Therefore this prototype does not claim to use that dataset, and it contains no fabricated public data or reference answers.

The [Data Dubai Terms & Conditions](https://data.dubai/en/terms-conditions) state that Open Data use is subject to the Open Data Licence and separately describe limits on general copying. Review the licence and obtain confirmation of reuse, attribution, and redistribution permissions for the exact dataset before importing or sharing it.

Open **Open-data tests** to download a JSON or CSV template. Import only a permitted, public, non-personal dataset package (maximum 500 KB) with:

- dataset title, HTTPS source URL, exact licence, source data date (or explicit unknown), access date, and transformation notes;
- source rows containing stable `rowId` values and original field names/values;
- exactly ten unique tests, with at least one each of `extraction`, `calculation`, `summary`, and `unanswerable`; every test needs a question, reference answer, evaluation method, referenced row IDs, and field names that exist in those rows.

Imports are stored locally and are not sent automatically. Select an imported test in Live model comparison to send the cited rows and question to both third-party routes, after accepting the Live warning. The reference answer is not included in the provider prompt. Demo Mode deliberately does not invent replies for imported data. Automated reference-string checks for scalar extraction/calculation are limited checks, not proof of truth; summaries and unanswerable cases require human review.

CSV columns are `id,type,question,expected_answer,source_rows_json,fields_json,evaluation_method,title,source_url,license,data_date,accessed_date,transformations`. The two `*_json` columns contain valid JSON arrays; `source_rows_json` items use `{"rowId":"...","fields":{"field":"value"}}`. Dataset metadata must be identical across all ten rows.

## Evaluation and approval limits

- Suitability is a weighted fit signal, separate from compliance and security findings.
- Human ratings remain pending until recorded: factual accuracy 50%, Arabic quality 25%, and source adherence 25%.
- The approval gate blocks when any applicable mandatory finding is not Met or lacks a justified “Not applicable” finding. Suitability cannot override the gate.
- Prototype evidence rules are illustrative and require validation against the applicable official policy. No UAE legal clauses are invented here.
- Live-provider identity, hosting, data retention/deletion, and independent security evidence are unavailable. No demo evidence is used to approve a live provider.
- The synthetic bilingual service guide and fixed demo replies are fictional. Limited tests do not prove security, accuracy, or compliance.
- Local storage and exported passports are demo records, not tamper-resistant audit logs or official certificates.

## Traceable source and evidence database

Open **Sources & guidance** in the sidebar. The browser-only prototype adds a versioned `evidenceDatabase` object to the existing `aigov-compass-demo-v1` local-storage record; it does not replace the current application state or require a database service. The logical collections are `sources`, `guidance`, `useCases`, `modelProfiles`, `tests`, `evidence`, `decisions`, `versions`, and `auditEvents`. Demo evaluations are mirrored into these separate collections when saved. Suitability figures in that database are explicitly labelled as a static demo heuristic, not model performance measurements.

The source catalogue was checked on 2026-10-27:

- UAE Government Portal **AI resources** and **Digital UAE** pages opened; their page titles and publisher were verified. Linked policy documents, publication dates, legal status, and applicability to a particular entity still require review.
- NIST **AI RMF Playbook** opened. Its page describes voluntary suggestions aligned with Govern, Map, Measure, and Manage, says it is not a checklist, and notes AI RMF 1.0 is being updated.
- OECD **AI Principles** page opened; it reports the initial 2019 adoption and May 2024 update.
- OWASP GenAI project page opened, but the current edition and detailed LLM Top 10 content still need review; the catalogue marks it accordingly.
- ISO **ISO/IEC 42001:2023** public page opened. The public summary describes an AI management-system standard and Plan-Do-Check-Act; the full licensed standard was not accessed. No clause numbers or conformity claims are included.
- The Dubai CPI metadata record is retained as **needs review** from the earlier project inspection: its page showed no data and disabled downloads on 2026-10-23. No rows from that dataset are present or used.

Every guidance entry links to one source and includes a short paraphrase, relevance, evidence to request, source reference, review status, reviewer, and last-review date. UAE sources are discovery references, not proof of a binding obligation. NIST/OECD/OWASP records are optional guidance. ISO is a licensed-standard reference requiring expert review. All proposal-to-use-case mappings are suggestions: an authorized reviewer must decide applicability and mandatory status. The catalogue is not exhaustive and does not establish legal compliance.

The catalogue includes review prompts for governance, privacy, transparency, fairness, security, performance, and human oversight. The added privacy, transparency, fairness, and human-oversight prompts are project-authored suggestions informed by the voluntary NIST Playbook; they are not quoted NIST controls, subcategory mappings, or legal requirements, and remain marked for expert review.

Use-case intake proposes guidance based on the task, language, sensitivity, hosting, and oversight fields. A reviewer can record applicability, mandatory status, reviewer name, and a rationale. Once an evaluation is created, linked evidence records can be updated with one of **Satisfied**, **Not satisfied**, **Insufficient evidence**, **Pending review**, or **Not applicable**. A mandatory item blocks a demo decision unless a reviewer records a reference, name, and date with a satisfied finding, or records a justified not-applicable finding. Merely adding a URL never satisfies a requirement. The existing demo evidence gates remain in place, and none of these prototype decisions are government approvals or certifications.

The database page provides search, source/domain/status filters, source links, a JSON export, and a full-workspace JSON backup. Import validates the supported schema and references, presents a preview, and merges new IDs only; existing IDs are not overwritten or deleted. To restore, choose **Import / restore JSON**, select a previously downloaded AIGov Compass backup, inspect the preview, and confirm the append-only merge. Keep the downloaded backup in a safe location. The export can include evaluation/use-case details and reviewer names; do not export or store personal, confidential, or secret government data. Browser storage and event history are not a protected government system or tamper-resistant audit log. Imported records are data only and are not sent to the assistant or external providers.
